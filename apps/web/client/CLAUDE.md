# CLAUDE.md — apps/web/client

Guidance for the web client. Extends the root [../../../CLAUDE.md](../../../CLAUDE.md); those rules still apply.

**Next.js 16 / React 19**, App Router, `cacheComponents` and the React Compiler on, shipped as a Node server (`output: 'standalone'`, see [Dockerfile](Dockerfile)). Caddy sits in front of it in [docker-compose.yml](../../../docker-compose.yml).

Architecture is **Feature-Sliced Design** with two local tweaks: `pages` → `views`, and the design system lives at the root as `ui-kit` rather than inside `shared`. Full rules: [docs/architecture/fsd.md](../../../docs/architecture/fsd.md); code style: [docs/guides/](../../../docs/guides/README.md).

Inside a slice: `index.ts`, `ui/`, `model/hooks/`, `model/context/<name>/` (context + `useX` consumer; the Provider is a `ui/` component fed by `model/hooks/use-<x>-state/`), `api/<resource>/` (+ `api/mappers/<name>/`), `lib/<concern>/`, `config/`. No runtime import cycles — `bun run lint:cycles` (madge, part of `verify`) guards it; rules in [client/structure/fsd-layers.md](../../../.claude/rules/client/structure/fsd-layers.md).

**Every thing is a folder.** A file with companions (`x.ts` + `x.types.ts` / `x.constants.ts` / `_tests/`) lives in its own `x/` with an `index.ts`; nothing lies flat next to another concern. `shared/lib` is flat, one folder per concern — helpers `shared/lib/<concern>/`, hooks `shared/lib/use-<x>/` — and `shared/constants` is `routes/`, `site-nav/`, `account-nav/`, `periods/`, `query-keys/`, `storage-keys/`. `ROUTES` is nested per page family (`ROUTES.tanks.detail(slug)`, `ROUTES.players.session({ nickname, sessionId })`, `ROUTES.account.overview`). Details: [fsd.md §4](../../../docs/architecture/fsd.md).

Imports go downward only: `app → views → widgets → features → entities → shared`. `ui-kit` sits beside `shared`: every layer may import it, and it may import `@/shared/*`. Alias `@/*` → `apps/web/client/*`.

## Conventions that bite

- **Public API**: import the slice (`@/features/search/command-palette`), never the domain group or past the barrel.
- **`ui-kit`** has one root barrel — `@/ui-kit`.
- **Middleware-safe imports.** `proxy.ts` bundles everything it reaches (`app/proxy`, `shared/api/http`, `shared/api/query-client`, `shared/api/source`), and that code must stay off the `@/shared/lib` and `@/shared/config` barrels, whose modules reach `shared/seo` (and through it `next/root-params`) and `next/font` ("'next/root-params' can only be used inside the App Directory"): it imports `@/shared/lib/env` (`isServer`, `isBrowser`), `@/shared/lib/route-param` (`decodeRouteParam`) and `@/shared/config/client-env` directly. `decodeRouteParam`, `isServer` and `useBreadcrumbs` (`@/shared/lib/use-breadcrumbs`, which reaches `shared/seo`) are left out of the `@/shared/lib` barrel — import them by path everywhere.
- **Client-safe barrels.** A barrel that client components import never re-exports a module using server-only APIs (`cacheLife`/`cacheTag` from `next/cache`, `next/headers`, `next-intl/server`, `shared/i18n/request`); those stay behind `server.ts` or a deep import. `shared/seo/index.ts` takes `ROUTE_STATIC_PARAMS` from `route-meta/route-meta.constants` for this reason: the `route-meta` barrel pulls `cacheLife` into the client bundle and only `next build` catches it, not typecheck or tests.
- **`model/` barrels** live in subfolders (`model/hooks/index.ts`), never a slice-level `model/index.ts`.
- **Components only render.** A component folder holds only `Name.tsx`, `Name.types.ts`, `Name.module.scss`, `index.ts` and nested `components/` (plus `.motion.ts` / `.variants.ts` if needed). State, effects, queries, handlers and derived data go to `model/hooks/use-<x>/use-<x>.ts` (+ `.types.ts`, `index.ts`), forms to `use-<x>-form/` (react-hook-form + zodResolver); pure helpers to `lib/<concern>/<concern>.ts` + `index.ts` + `_tests/`; constants to `config/<concern>.constants.ts`. Never `*.helpers.ts` / `*.utils.ts` / `*.constants.ts` inside a component folder. One component per folder; a `ui/` root is either one flat main component plus `components/`, or a folder per exported component — never a flat component beside sibling folders. Details: [guides/client/slice-ui.md §2](../../../docs/guides/client/slice-ui.md).
- **No clock in render.** `cacheComponents` prerenders Client Components, so the current time comes from `useClientNow()` / `useCountdown` in `@/shared/lib` (`null` until the browser renders), never `Date.now()`, `new Date()` or next-intl's `useNow` during render. Details: [client/rendering/ssr.md](../../../.claude/rules/client/rendering/ssr.md).
- **Contracts** come from `@otmetki/schemas` or the generated `z*` schemas in `shared/api/generated/zod.gen.ts` (re-exported by the slice `api/`); a form schema builds on them (`zCreateClanEvent.shape.title`) rather than retyping limits. Icons come from `@otmetki/icons` (next to `lucide-react`).
- **Styling** is SCSS modules; token values come from `@otmetki/design-tokens` (shared with the modpack's in-game window) and `shared/styles/_tokens.scss` emits them as CSS variables; breakpoints (`xs` … `4xl`) and mixins live in `shared/styles/`. `stylelint` runs on every `*.scss`. No CSS-in-JS; `class-variance-authority` only maps variant props to module classes (`Button.variants.ts`).
- **Two themes.** Dark (default) and light, switched by `next-themes` through `data-theme` on `<html>`. A colour token goes into both palettes of `@otmetki/design-tokens`; components read tokens and carry no theme code.
- **Tank renders** come from the Lesta API (`images` on `VehicleSummary`) and are shown only through `TankImage` from `@/entities/tank/tank` (`contour` / `small` / `big`, native size, class-glyph fallback, nation-flag backdrop on `big`). Never upscale a render past 160 px wide; the allowed remote image hosts are `api.tanki.su/static/**` and the `unicum-gg/wot.assets` / `wot.maps` mirrors on raw.githubusercontent.com (`config/build.ts`).
- **Rating colours** go through `ratingTone` / `toneOfTier` from `@/shared/lib` (nine `@otmetki/ratings` tiers → six tones) plus `data-tone` and `@include tone`. The display settings can swap the tones for the XVM scale (`data-rating-palette='xvm'` on `<html>`, overrides in `_tokens.scss`).
- **Fonts**: Fira Sans Condensed (display, numbers), Fira Sans (body), JetBrains Mono (HUD labels), loaded through `next/font/google` in `shared/config/fonts` (OG images draw with Tektur / Onest, `shared/seo/og`).
- **Page headers.** Two patterns, chosen by page type. `PageHero` (a full-bleed band with art and key figures) opens a section landing whose content is a data set or a product pitch: rankings, catalogues, stats hubs (`/tanks`, `/t`, `/marks`, `/top`, `/pulse`, `/modes`, `/status`), `/mod`, `/plus`; the page body below it sits in its own `page()` container (`TreePage`). `PageHeader` (a panel in the page column) heads everything else: tools and calculators, forms and editors, feeds and directories of user content (news, blog, guides, coaches, tactics, tournaments, replays), detail and sub-pages. Every page except `/` and the `/me` cabinet (where `AccountShell`'s nav marks the place) passes `breadcrumbs`: section → page — the shared builder (`useBreadcrumbs`, `withHomeCrumb`) puts «Главная» in front, so a trail never lists it, and the last crumb is the current page, unlinked. The `/me` cabinet heads every page with `SectionHeader as='h1'`. `/tanks` and `/t` are the two tabs of the «Танки» hub (`widgets/tank/tanks-hub-nav`): both URLs stay, both crumb trails go through «Танки».
- **Site navigation** is one source, `shared/constants/site-nav`: `SITE_LINKS` (every section once: key, href, icon; labels `nav.items.*`, hints `nav.hints.*`), `SITE_NAV.menu` (the header: six entries — the dropdowns Игроки / Танки / Игра / Сообщество, at most five links each, and the direct links Отметки and Модпак), `SITE_HUB_GROUPS` (every section, grouped for `/hub` «Все разделы» and the footer sitemap). The mobile drawer shows the four dropdowns plus the direct links, `/hub` and Plus; the command palette lists all of `SITE_LINKS`. A new page gets a `SITE_LINKS` entry and a place in `SITE_HUB_GROUPS` (the `nav-match` tests enforce both); it joins the header only by replacing a link there. In the installed PWA (`display-mode: standalone`) below `lg`, `widgets/site/tab-bar` adds a bottom tab bar (Главная, Поиск, Отметки, Кабинет, Ещё → `/hub`); in the browser it renders nothing.
- **Browser-stored state.** `createStoredStore({ key, parse })` + `useStoredStore(store)` (`@/shared/lib`) is the SSR-safe localStorage store: `null` on the server and during hydration, one cached parse per raw value (so `useSyncExternalStore` gets a stable snapshot), writes notify every subscriber and other tabs follow through the `storage` event. `parse` validates the stored JSON with a schema derived from `@otmetki/schemas`, because anything in localStorage is untrusted.
- **Compare tray.** `features/compare/compare-selection` keeps the per-browser selection — tanks and players, up to `COMPARE_SELECTION.limit` (10) of each, plus the kind the tray shows — and exports `CompareToggle` (`variant='icon'` for table rows and cards, `'button'` for page headers). `widgets/compare/compare-tray`, mounted once in the `(site)` layout, docks the selection at the bottom (a bottom sheet below `lg`, above the PWA tab bar) and opens `/tanks/compare` or `/compare/players` with the first `COMPARE.maxTanks` / `COMPARE.maxPlayers` ids; picks beyond that stay in the tray, dimmed. A tank or player card, row or page header adds a `CompareToggle` instead of its own «Сравнить» link; `TankCard` takes it through its `action` slot, because the card itself is a link.
- **Own nickname and the home dashboard.** `entities/player/own-player` stores the visitor's own account (`accountId` + `nickname`) locally, without a login; `features/player/own-nickname` has `NicknameForm` (react-hook-form over `nicknameSchema`, resolved through `getPlayer`: a 404 is «игрок не найден») and `OwnPlayerMenu`, the «Ваш ник?» / nickname item in the header utility bar. The home `MyDashboard` (`#my`) reads the entity's `usePlayerDigest` (profile, last session, marks). Its frame has a fixed height per breakpoint (`--dashboard-height`) and every state — skeleton before hydration, the «Ваш ник?» form over a ghost of the dashboard, not found, error, ready — fills that same box, so the server render (which cannot read localStorage) never shifts the page. New dashboard content has to fit those heights.
- **Motion.** `AppProviders` wraps the app in `MotionConfig reducedMotion='user'` and `LazyMotion strict` whose features (`domMax`) load in their own chunk (`loadMotionFeatures`), so components render `m.*` (`import * as m from 'motion/react-m'`), never `motion.*` (strict throws, and `motion/react`'s `m` re-export drags the full component in). Shared durations, transitions and variants are `MOTION`, `MOTION_TRANSITION`, `MOTION_VARIANTS` (`listItem`, `panel`) in `shared/lib/motion`; one-off presets go in `<Component>.motion.ts`. Animate `transform` and `opacity` only, and never on first paint: lists use `AnimatePresence initial={false}` (+ `layout` / `mode='popLayout'` for enter, exit and reorder), and `Reveal` (`useScrollReveal`) hides a block only when it mounts below the fold, then fades it in once on scroll — above-the-fold content is never hidden, so it cannot delay LCP. Popups, dialogs and tab panels animate in CSS off Base UI's `data-starting-style` / `data-activation-direction` (`popup-motion` mixin). Page transitions are React `<ViewTransition>` around the `(site)` layout's `children`: the locale `Link` tags every navigation with the `page` transition type and only that type crossfades `main` (`page-swap` in `app/globals.scss`); the header and the tab bar keep their own `view-transition-name` so they stay put, and `prefers-reduced-motion` turns it all off.
- **`ui-kit`** wraps `@base-ui/react` primitives; charts are visx (`ChartKit`), the command palette is `cmdk`, `DataTable` is TanStack Table + Virtual and opts out of the React Compiler with `'use no memo'` (as do the three.js / R3F viewers). Generic hooks come from `@siberiacancode/reactuse`.

## Locales live in the URL

`/` is Russian, `/en` is English. The default locale carries no prefix (`localePrefix: 'as-needed'`), and `proxy.ts` — Next 16's name for middleware — rewrites to the locale segment. For entity URLs it also asks the API (`app/proxy/entity-presence`): a 404 becomes the localized not-found page with a real 404 status, and a non-canonical key (numeric tank id, clan id or lower-case tag, map id, account id) gets a 308 to the slug, tag or nickname the API spells. Viewer-scoped entities (guides, replays, tactics, tournaments, competitions, coaches) are not checked there, because a draft or private item 404s without the owner's session.

- **Never import `Link`, `useRouter` or `usePathname` from `next/*`.** Use `@/shared/i18n/navigation`, which keeps the locale in every href.
- **`next/root-params` is how server code reads the locale** (`rootParams.locale()` in layouts, pages and `generateMetadata`).
- Every user-visible string goes through next-intl, in both languages: `shared/i18n/locales/{ru,en}/<namespace>.json` (one file per namespace, same keys in both languages).
- **Client messages are scoped per route.** The root layout hands the browser only `ROOT_MESSAGES` (`app/messages`: what the layouts, boundaries and providers render); a page, layout or `loading.tsx` whose client components read more exports `withMessages({ component: Page, messages: ['tank', 'plus.teaser'] })`, which nests a provider with `ROOT_MESSAGES` plus its list (and the page-scoped mutation toast translator). `app/messages/_tests/route-messages.test.ts` walks each route's client import graph (`config/message-usage`) and fails on a missing or unused entry, so a new `useTranslations('x')` in a client component means a new entry there. Server components read messages through `getTranslations` and need none.

## Data

- **Requests live in their slice.** `shared/api` keeps only infrastructure (axios instance, bearer token, generated OpenAPI client + `query-options`, `fromServer`/`fromSdk`/`fromAuth` and the error classes, the better-auth client, `queryClient`). A read several slices need goes to `entities/<domain>/<slice>/api/<resource>/`, an action several slices trigger to `features/<domain>/<slice>/api/<resource>/`, anything one screen alone uses to `views/<view>/api/<resource>/`; the slice barrel re-exports it. Query keys stay in the shared `QUERY_KEYS` registry because invalidation crosses slices. Hooks live in the slice that owns them (`views/home/model/hooks`, `features/search/command-palette/model/hooks`).
- **No mocks.** Every request goes to the server through `fromServer` (`shared/api/source`), which turns a 404 into `NotFoundError` and a 401 into `UnauthorizedError`. With no data a screen shows its empty state; with the API down, its error state with a retry. Queries run in the browser, so `next build` and the e2e smoke need no running server.
- Env is read only through `@/shared/config` (`env`; `@/shared/config/client-env` from code `proxy.ts` reaches), which validates it with Zod. Server-only env (`INTERNAL_API_TOKEN` and `LESTA_NOTICE` (`true`/`false`), both required, no default) is read lazily through `serverEnv()` in `@/shared/config/server-env`; `LESTA_NOTICE` is a runtime switch read per request (`entities/app/lesta-notice`), so the image never bakes it in. The axios instance adds the token as `x-otmetki-internal-token` to every server-side request, and `proxy.ts` forwards the visitor IP as `x-otmetki-client-ip` so the API throttles per visitor. `next.config.ts` loads `NEXT_PUBLIC_*`, `INTERNAL_API_TOKEN` and `LESTA_NOTICE` from the root `.env` via `config/root-env.ts`; `NEXT_PUBLIC_APP_VERSION` comes from the root `package.json`, and the build arg `GIT_COMMIT_SHA` joins it in the service worker's precache revision.

### Loading, empty and error states

- **`QueryState`** (`@/ui-kit`) renders a query's skeleton, empty, error-with-retry and data states: `<QueryState query={q} skeleton={…} empty={…} isEmpty={…}>{(data) => …}</QueryState>`. Lists and sections use it rather than hand-rolled `isLoading` branches.
- **No layout shift from loading.** `QueryState` and `PagedList` measure their skeleton on mount (`useReservedHeight`) and give a following error or empty state that height as `min-height`, so a failed or empty load keeps the reserved footprint. The data state is not reserved, so a skeleton mirrors the data layout: the same rows, the mobile cards (`DataTable isLoading` gets the same `renderCard`), the split panels (`RngSkeleton`). An empty list that `DataTable` would render inside itself goes through `QueryState`'s `isEmpty`/`empty` instead, and a block that exists only while loading or after success (`ClanLeaders`) stays mounted on error. Check a page with the CLS probe (production build, a `layout-shift` observer, target < 0.05) with the API up and with it blocked.
- **`ResourceGate`** (`@/widgets/site/resource-missing`) wraps `QueryState` for a page about one resource: a 404 from the API calls `notFound()` (or shows the `notFound` message when one is given), any other error shows `ResourceMissing` with a retry; its `header` keeps the page's `PageHeader` (crumbs) above an error or not-found state.
- **Pagination** is one model: `useOffsetInfiniteList` + «Показать ещё» — card lists render `PagedList`, tables (`/replays`, `/guides`) put the same `LoadMore` in the `DataTable` footer; no prev/next pagers or page numbers in the URL. The blog and the streamers directory keep their own infinite feeds.
- **Route fallbacks** match the view's header: `PageHeaderFallback` (page column + `PageHeaderSkeleton`, optional body skeleton as children) for `PageHeader` pages, `PageHeroFallback` (optional `hasActionStrip` and body) for `PageHero` pages; heavy detail views export their own body skeleton (`ReplaySkeleton`, `BoardSkeleton`, `OperationSkeleton`, …) used both in the route fallback and in their `ResourceGate`. A view whose header would read search params keeps those reads below the header (`/marks`, `/top`) or ships a fallback that carries the real h1 (`/tanks`), so the prerendered shell has the page title.
- **Tables** are `DataTable` from `@/ui-kit`; column definitions are typed `TableColumn<Row>` (= TanStack `ColumnDef<Row, any>`) and built in a `use-<x>-columns` hook. A column picker or CSV export belongs to the view that owns the table (e.g. `views/tanks`: `TableTools`, `lib/tanks-csv`). Below `md` a table keeps the name column and its key metric readable: secondary columns get `meta.hideBelow`, and row toggles (pin, compare) move off the row — `hideBelow: ROW_ACTIONS.showBelow` on their columns plus one `RowActions` column (`@/widgets/table/row-actions`, `meta.showBelow`) that opens them in a `RowMenu` popover. A player row drops its compare toggle there instead, because the profile it links to carries one. A click inside a popover a row opened never activates the row (`[role="dialog"]` counts as an interactive target).

### Server rendering: route meta and prefetch

Queries run in the browser; the server only renders metadata, 404s and a warm cache for the entity pages.

- **`server.ts` entries.** Server-only code of a slice is exported from its `server.ts` (`import 'server-only'`), never from `index.ts`: `entities/{tank/tank,clan/clan,player/profile,map/map,replay/replay,streamer/streamer,blog/post,guide/guide,coaching/coach,competition/competition,tournament/tournament}/server.ts` export the route lookups (`api/route-meta/`: `tankRouteEntity`, `topTankSlugs`, …) and OG sources; `entities/app/lesta-notice/server.ts` exports `readLestaNotice` (the runtime `LESTA_NOTICE` switch behind `connection()`, which the `(site)` layout hands to `LestaNoticeProvider` as a promise so the prerendered shell never bakes it in); `views/{home,tank,tanks,vehicle-catalog,player-profile,clan,map,marks,top,build,achievements,supertest,plus,streamer,streamers-directory}/server.ts` export the page's prefetch (`api/page-state/`: `tankPageState`, …).
- **Route meta.** `generateMetadata` and the page call `requireRouteEntity(xRouteEntity(slug))` (`@/shared/seo/require-route-entity`): a 404 from the API becomes `notFound()`, any other failure renders the page anyway (`routeEntity` in `shared/seo/route-meta`), so an API outage never turns into 404s. `generateStaticParams` and `app/sitemap.ts` use the `top*Slugs` / `*Slugs` helpers with a fallback. Metadata goes through `createPageMetadata` (canonical, hreflang alternates, OG image).
- **Prefetch pattern.** A page-state function is `'use cache'` + `cacheLife(PREFETCH_CACHE_LIFE)` and returns `prefetchState((client) => [client.fetchQuery(…)])` (dehydrated state from a fresh server `QueryClient`). The page renders `<Suspense><PrefetchBoundary state={xPageState(slug)}><XPage /></PrefetchBoundary></Suspense>`; `PrefetchBoundary` swallows a failed prefetch, so the browser simply fetches again.

### Service worker and security headers

- **Service worker** (Serwist, `app/sw.ts`, served from `app/serwist/[path]`): precache plus Serwist's `defaultCache` runtime rules wrapped in `sameOriginCaching` (`shared/lib/same-origin-caching`), so only same-origin requests are cached — API responses (another origin) always go to the network. It also shows web push notifications and focuses/opens the target URL on click.
- **CSP** is set in `next.config.ts` from `config/security-headers.ts`, without nonces (they would make every page dynamic under `cacheComponents`): `script-src 'self' 'unsafe-inline'`, `connect-src 'self'` + the API origin and its `ws(s)` origin, `frame-ancestors 'none'`. Per-route overrides: `/login` allows the Telegram widget, `/overlay/*` is frameable by the site, `/tg/*` by web.telegram.org, `/vk/*` by vk.com / vk.ru, `/twitch-panel` by Twitch. A new third-party script, frame or connection needs an entry there.

## Lesta terms in the UI

Every page renders `SiteFooter`, which carries the Lesta copyright, the data-source link to tanki.su and the fan-project disclaimer ([docs/research/data/lesta-api.md](../../../docs/research/data/lesta-api.md)). The block itself is `LestaAttribution` (`@/entities/app/lesta-attribution`, plus the Lesta support link and our copyright); pages outside the `(site)` layout render it themselves — `global-error`, `[locale]/error` and `[locale]/not-found`, the mini-app footer, and the compact one-line variant in the `(overlay)` and `(tma)` error boundaries. Don't add a layout that skips it; the e2e smoke checks it.
