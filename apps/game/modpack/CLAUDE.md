# CLAUDE.md — apps/game/modpack

Guidance for the game-client modpack. Extends the root [../../../CLAUDE.md](../../../CLAUDE.md); those rules still apply. The full reference — layout, hooks, payloads, build, install — is [README.md](README.md).

**Python 2.7** packages the «Мир танков» client loads from `mods/<client version>/` as `.mtmod` (Lesta 1.35+; `.wotmod` for WG). It is a bun workspace (`@otmetki/modpack`: `test`, `lint`, `build` scripts). **Everything Python runs on 2.7.18**, the version the client embeds: the game code, its tests and the host tooling (build, catalogue, dev loop, vendoring). mise pins it (`conda:python` in the root `mise.toml`); the tooling's packages are the last 2.7 releases in `tools/requirements.txt` (`python -m ensurepip`, then `python -m pip install -r tools/requirements.txt`). There is no Python 3: SVG is drawn by `@resvg/resvg-js` on Node (`tools/build/rasterize.mjs`), ruff is its standalone binary (`ruff.toml`). Its Python half is not part of `bun run verify`; `ui-web` (the in-game window's TypeScript and SCSS) is: typecheck, ESLint, Prettier, Stylelint (its own `ui-web/stylelint.config.mjs` adds the Gameface bans).

## Two kinds of code

| Where                                     | What                                 | Tested                 |
| ----------------------------------------- | ------------------------------------ | ---------------------- |
| Any `*.py` outside `client/` and `entry/` | Pure logic, no client imports        | its package's `tests/` |
| `client/` folders, `entry/`               | Glue that imports `BigWorld` / `gui` | the import smoke only  |

Keep as much as possible in the pure half — it is the only half the checks can run.

## Rules

- **Python 2.7 syntax in the game sources.** No f-strings, annotations, `async`, walrus or `match`. Python-3-only modules (`urllib.request`, `pathlib`, `typing`, …) only inside a `try/except ImportError` fallback. The suite runs on 2.7, so `tools/tests/test_py27_compat.py` compiles every source with the 2.7 compiler and adds the checks it cannot (print statements, unguarded py3-only imports, non-ASCII bytes literals). Tests mirror the client: `_support` sets the default encoding to UTF-8 as the client's `bw_site.py` does, and keeps modules a test drops from `sys.modules` alive (Python 2 clears a freed module's globals).
- **No load order.** The client imports `mod_*.pyc` in hash order. Never assume the core, the app or another feature is initialised first: features register through `core.registry` (`register()` in their entry script), and the app binds when it starts.
- **A feature is a folder:** `features/<id>/` with `__init__.py` (`FEATURE_ID`, `PACKAGE_ID`, `VERSION`, `create(app)`, `register()`), `entry/mod_otmetki_<id>.py`, and the packages `model/` (pure), `client/` (glue on `app.bus`), `settings/`, `i18n/`, plus `tests/`. `tools/tests/test_layout.py` checks the shape. Core and companion follow the same rule: one folder per concern, glue in its `client/` subfolder, constants in its `constants.py`.
- **Feature glue starts from core.** `FeatureComponent`, `BattlePanel`, `NativeSettingsComponent`, `Ticker`, `core.client.game` / `garage` helpers and `ReasonError` instead of per-feature copies; core guards every hook, so handlers carry no try/except of their own, and a client read that may fail on API drift is `@core.log.guarded(context, fallback)`.
- **Libraries before custom code.** `packages/core/vendor` holds six, blinker, attrs and enum34 at pinned py2.7 versions with their licences; `python tools/vendor/vendor.py` rewrites it from the pinned wheels (`--check` verifies). Never edit vendored files by hand.
- **HUD panels take part in HUD edit mode** through `core.hud.HudPreview` (`hud_edit`, `hud_describe` on `app.bus`), with sample text from the feature's `model/preview.py`.
- **Every package has a catalog entry** in `catalog/catalog.json` (titles ru/en, category, presets, fair-play note, preview in `catalog/previews/`) and a bilingual `## <id> <version>` entry (`### ru`, `### en`) in `CHANGELOG.md`. `tools/build/setupkit/manifest/tests/test_manifest.py` and `tools/build/tests/test_changelog.py` fail without them. Third-party runtime mods (OpenWG Gameface and ModsList 1.6.01, both required) are `kind: "dependency"` entries of the same list, pinned by sha256 with their licence; a component that starts drawing a HUD or hangar label (`BattlePanel`, `HangarLabel`, `hud_layer(`, `app.ui.show(`) or importing `openwg_gameface` joins their `requiredBy`, which `tools/build/setupkit/manifest/tests/test_dependencies.py` checks against the code (`from gui.modsListApi import` for ModsList).
- **Settings stay in the companion schema** (`packages/companion/config/`) so `config.json` keeps a switch while its feature is not installed; a feature's `settings` lists the keys it reads. A battle HUD component's look and position live in its own schema-checked section of `components.json` (`core/hud`), its on/off switch in `config.json`.
- **The settings window is behind `SettingsView`** (`companion/settings_ui/client`): the app starts with the null view, and the Gameface window (`packages/ui`) replaces it with `attach_settings_view` when the ui package starts. It opens only from its ModsList entry (ModsList 1.6.01, the last release that runs on Lesta; master needs WG 2.4.1+); there is no HUD button and no hotkey, and the on-screen HUD edit mode ends with Esc or that entry. Never add another settings stack (ModsSettingsAPI). The window renders every card from the feature's own schema, so a new feature needs no UI code: `settings.SETTINGS` (its config.json switch), `settings.SCHEMA` (its components.json section), optional `GROUP`, labels `component_<id>`, `<id>_<key>`, `<id>_<key>_<value>` in its i18n; buttons and list pages through `ui_actions()` / `ui_page()` / `ui_action()` on the feature instance, a full-window visual editor (live preview, grouped fields, thumbnail gallery, swatches) through `ui_editor()`, a card picture through `ui_thumb()`, per-choice pictures through `ui_gallery()`, fields folded under «Дополнительно» through `ui_advanced()`, a second component of one feature (its own row, switch, section and editor page) through `settings.PARTS` (README «In-game UI»).
- **`ui-web` is a standard Vite React app with the web client's Feature-Sliced Design layers under `src/`** ([docs/architecture/fsd.md](../../../docs/architecture/fsd.md)) and no `app` layer; `@/` = `ui-web/src/`. The pages are `ui-web/pages/*.html` (built to the same names at the root of `packages/ui/gameface`); their entries are `src/<page>.tsx` (`main.tsx` for `index.html`, `hud.tsx`, `viewer.tsx`, plus `advisor.ts` and the dev mock's `dev.ts`), each thin; then `views/` (`settings`, `hud`, `hit-viewer`, `preset-advisor`, each with its page config), `widgets/<domain>/<slice>`, `features/<domain>/<slice>` (what the player does), `entities/<domain>/<slice>` (`window/window-state`, `replay/replay`, `hud/<kind>`, `hud/panel-layout`), project-agnostic `shared/` (page global styles in `shared/styles`, the dev mock bridge in `shared/api/gameface/dev-bridge`) and `ui-kit/` (imported only as `@/ui-kit`). Imports go downward only, never between slices of one layer, through each slice's `index.ts` (`@/…` across slices, relative inside one); the HUD widget registry composes every `entities/hud/<kind>`, so it is `features/hud/widget-registry`. Entries import `@/shared/lib/engine-shims/install` first (React's scheduler needs its host APIs when it loads), then `onDomReady` + `mountOnce`; React 19, so no `onWheel` in JSX (native non-passive listener via `shared/lib/wheel-scroll`) and hooks from `@siberiacancode/reactuse` before hand-written effects; components only render, hooks in `model/hooks`, constants in `config/`, the Gameface globals only behind `shared/api/gameface` (mock in `shared/api/gameface/mock`). No `ul`/`li`/`dl`/`select` elements or `radio`/`range`/`checkbox` inputs (Gameface polyfills or lacks them; ESLint, Stylelint and the bundle test enforce it); both pages ship their script as a classic IIFE at the end of the body. Anything that opens over the page (a confirmation, a list, a focused field) registers with `useEscapeLayer` so Esc steps back through it; tooltips go through `useTooltip` (the client's own tooltip), never a `title` attribute. After a change, `bun run ui:build` and commit `packages/ui/gameface` (README «In-game UI»).
- **Client settings only through the game's own options.** Components that change the player's client settings (`minimap`, `camera`, `crosshair`, `hangar_tweaks`) go through `core/client/native` with `native` meaning "leave the game's value", and write only on the player's change in the hangar (or on the player's own key press in battle: `battle_hotkeys`). The one exception, the owner's decision: the minimap's last-seen spots and names are switched from the game's `never` to always once per install (README «minimap»). Anything beyond the game's own options (camera distance, free look, Flash patches) stays out until Lesta confirms it.
- **Hangar actions only on the player's request.** Components that send client requests (`hangar_tweaks` quick actions, `auto_resupply`) run them from a window button, never on their own (the one exception is `auto_reserves`: its off-by-default switch and reserve picks are the request; `depot_seller` always confirms with the items and credits); overrides of client views (`chat_filter`, `notification_filter`, `hangar_cleaner`) call the original unless their switch hides the element, and never touch the player's own lines or plain messages. README «Left out of the component catalogue» lists what stays out and why.
- **Fair play is a hard constraint.** Read only the player's own data; never read or show enemy positions, reload timers, aim or spotting data. Never serialise the `vehicles`, `players` or `avatars` blocks of battle results — `test_payload.BattleEventTest.test_never_leaks_other_players` enforces it.
- **Nothing is sent before the player binds the mod**, and every feature can be switched off in settings. The documented exception (README «Fair play»): unsigned `GET`s of public reference data with no account, device or battle data, today `update_notice` (game version), `preset_advisor` and `core/client/moe` (a tank id); a new one needs the same justification in the README, otherwise it waits for the binding.
- **Network only through `core/net/transport`** (urllib on a worker thread, verified TLS, no redirects, capped answers), never `BigWorld.fetchURL` (its certificate check is unverified). `server_url` is honoured only in a development install (`companion/config.is_dev_install`); a release always talks to the production API.
- **The contract is the API's contract.** A payload change updates `contract/*.json` and the server's ingest schema together; the server's tests read `contract/examples/ingest.example.json`.
- **Own reads go through `core/client/me`.** A feature that reads the bound account's data from the site uses `post_signed` (and the shared `tank_ratings` read for tank rows), never its own signing; an endpoint the server does not serve yet gets its contract in `contract/` and a README TODO line, and the feature stays silent until it answers.
- **Settings files a player cannot recreate go through `core.durable.open_config`** (config, components, profiles, state; `credentials.json` through `open_secret_pair`: the game-folder half has no secret, the %APPDATA% half seals it with DPAPI, never written in plain text): it mirrors them into `%APPDATA%\TriOtmetki` because a mod installer or cleaner may wipe `mods/configs`; the newer copy wins on load (README «Durable settings»). A new file of that kind joins `DURABLE_FILES`.
- **Release packages ship `.pyc`.** The production client loads only `mod_*.pyc`.

## Commands

```bash
mise install && python -m ensurepip && python -m pip install -r apps/game/modpack/tools/requirements.txt   # Python 2.7.18 + the tooling's packages
bun run test:modpack                                         # every tests/ folder (game code and tooling) on Python 2.7: tools/run_tests.py
cd apps/game/modpack && ruff check .                              # lint (standalone ruff, ruff.toml): 120 columns, blank lines, complexity/size limits, PT018, RET, SIM (pyupgrade and ruff format off: py2.7; core/vendor excluded)
cd apps/game/modpack && pyright                                   # editor config check (pyrightconfig.json, extended by the repo root's): game imports (`gui.mods.otmetki.*`, `....core.*`, `otmetki.*`, BigWorld) resolve only in the client, so reportMissingImports is off for packages/, features/ and the tools that import the mapped tree; typeCheckingMode off (Pylance's default)
python apps/game/modpack/tools/vendor/vendor.py --check           # core/vendor matches the pinned wheels (downloads them)
python apps/game/modpack/tools/build/build.py                     # dev build -> dist/*.mtmod, one per package
python apps/game/modpack/tools/build/build.py --single --require-pyc   # release, single package -> dist/single/ (never next to the split set)
python apps/game/modpack/tools/build/build.py --dry-run           # list packages and in-game paths, write nothing
cd apps/game/modpack && bun run ui:build                          # rebuild packages/ui/gameface from ui-web with Vite (commit the result)
cd apps/game/modpack && bun run ui:dev                            # the settings window in a browser, with a mock Gameface bridge
cd apps/game/modpack && bun run ui:test                           # ui-web tests, Vitest project modpack-ui (also in the repo's `bun run test`)
cd apps/game/modpack && bun run build:catalog                   # components.json + previews for the manager -> dist/catalog (previews need Node: rasterize.mjs)
cd apps/game/modpack && bun run dev:install [ID ...] [--dry-run]   # dev loop: build + install into <client>/mods/<version>/otmetki-dev (OTMETKI_GAME_DIR or the manager's detection; refuses next to a manager install)
cd apps/game/modpack && bun run dev:watch [ID ...]                # the same, then rebuild + reinstall on change (restart the client: no hot reload)
cd apps/game/modpack && bun run dev:uninstall                     # remove exactly what the dev loop installed (its otmetki-dev.json manifest)
cd apps/game/modpack && bun run dev:log                           # tail the client's python.log, [OTMETKI] lines and their tracebacks; dev:status prints the detected client
```

Every `python` above is 2.7 (`python tools/run_tests.py` refuses another version). CI takes every tool from `mise.toml`: [.github/actions/setup](../../../.github/actions/setup/action.yml) with `python: 'true'` installs the same 2.7.18 plus `tools/requirements.txt`. The deploy workflow's checks run `test:modpack` ([.github/workflows/deploy.yml](../../../.github/workflows/deploy.yml)); the release workflow's modpack job ([.github/workflows/release.yml](../../../.github/workflows/release.yml)) runs the suite and `ruff check .`, builds the packages with `owg_python_compiler` and the component catalogue (`components.json` + previews, `setupkit --strict`) for the manager. Players install through the manager ([apps/game/manager](../manager/README.md)); there is no separate installer.
